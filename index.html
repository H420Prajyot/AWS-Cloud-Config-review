1. Objective

This document provides the step-by-step procedure to configure AWS CLI access, validate permissions, execute automated security assessment tools, and perform manual security checks across two AWS accounts provided by the client.

The assessment will cover AWS services such as:

  • Identity and Access Management (IAM)
  • Simple Storage Service (S3)
  • Elastic Compute Cloud (EC2)
  • Virtual Private Cloud (VPC)
  • Relational Database Service (RDS)
  • Lambda
  • CloudTrail
  • CloudWatch
  • GuardDuty
  • Security Hub
  • AWS configuration and security posture checks

2. Prerequisites

The client has provided:

  • AWS Access Key ID
  • AWS Secret Access Key
  • Credentials for Account 1 and Account 2

Required tools:

ToolPurpose
AWS CLIAWS account connectivity and manual validation
ScoutSuiteAWS security posture assessment
ProwlerCIS/NIST/ISO compliance and security checks

3. Configure AWS CLI Profiles

3.1 Configure Account 1

Execute the command and provide the Account 1 credentials.

aws configure --profile client-account1
AWS Access Key ID: <Paste Account 1 Access Key>
AWS Secret Access Key: <Paste Account 1 Secret Key>
Default region name: ap-south-1
Default output format: json

3.2 Configure Account 2

Execute the command and provide the Account 2 credentials.

aws configure --profile client-account2
AWS Access Key ID: <Paste Account 2 Access Key>
AWS Secret Access Key: <Paste Account 2 Secret Key>
Default region name: ap-south-1
Default output format: json

4. Validate AWS Connectivity

Verify access to both accounts.

Account 1

aws sts get-caller-identity --profile client-account1

Account 2

aws sts get-caller-identity --profile client-account2

Expected output: AWS Account ID, IAM User ARN, User ID. Successful execution confirms AWS connectivity.

5. Validate IAM Permissions

Before starting the assessment, verify the permissions assigned to the IAM user.

Check Attached Policies — Account 1

aws iam list-attached-user-policies --user-name <IAM-username> --profile client-account1

Check Inline Policies — Account 1

aws iam list-user-policies --user-name <IAM-username> --profile client-account1

Repeat the same commands for Account 2.

Required Permissions

The IAM user should ideally have one of the below managed policies:

  • SecurityAudit
  • ReadOnlyAccess

Insufficient permissions may result in incomplete scan coverage or permission errors.

6. Execute ScoutSuite Assessment

Installation

pip install scoutsuite

Run Assessment — Account 1

scout aws --profile client-account1 --report-dir ./scout-account1

Run Assessment — Account 2

scout aws --profile client-account2 --report-dir ./scout-account2

Report Location

ScoutSuite generates an HTML-based report.

Windows:
start scout-account1/scoutsuite-report/scoutsuite_results.html

Linux/Mac:
xdg-open scout-account1/scoutsuite-report/scoutsuite_results.html

ScoutSuite Coverage

  • IAM security configuration
  • S3 bucket security
  • EC2 configuration
  • Network security
  • RDS configuration
  • Lambda security
  • Logging and monitoring
  • CloudTrail configuration

7. Execute Prowler Assessment

Installation

pip install prowler

Full Security Assessment — Account 1

prowler aws --profile client-account1 -M json html -o ./prowler-account1

Full Security Assessment — Account 2

prowler aws --profile client-account2 -M json html -o ./prowler-account2

Compliance-Based Assessment

Example: CIS AWS Benchmark Level 1

prowler aws --profile client-account1 --compliance cis_level1_aws

Prowler Coverage

  • CIS AWS Benchmark
  • NIST controls
  • ISO 27001 security requirements

Output includes: Pass, Fail, Warning, Compliance mapping.

8. Manual Security Validation Checks

8.1 Root Account MFA Validation

aws iam get-account-summary --profile client-account1 | grep -i mfa

Validation: Root MFA enabled → Secure. Root MFA disabled → Finding.

8.2 IAM User Enumeration

aws iam list-users --profile client-account1

Review: Unused users; Excessive privileges; Suspicious accounts.

8.3 Password Policy Validation

aws iam get-account-password-policy --profile client-account1

Check: Minimum password length; Complexity requirement; Password expiry; Password reuse restriction.

8.4 CloudTrail Validation

aws cloudtrail describe-trails --profile client-account1
aws cloudtrail get-trail-status --name <trail-name> --profile client-account1

Validate: Logging enabled; Multi-region enabled; Log validation enabled.

8.5 S3 Bucket Enumeration

aws s3 ls --profile client-account1

Review: Public exposure; Encryption; Access permissions.

8.6 S3 Public Access Block Validation

aws s3control get-public-access-block --account-id <Account-ID> --profile client-account1

Validate: Block public ACL; Block public policy; Ignore public ACL.

8.7 GuardDuty Validation

aws guardduty list-detectors --profile client-account1

Verify: GuardDuty enabled; Detector active.

8.8 Security Hub Validation

aws securityhub describe-hub --profile client-account1

Verify: Security Hub enabled; Security standards enabled.

9. Multi-Region Security Validation

AWS resources can exist across multiple regions. Validate active regions.

List Enabled Regions

aws ec2 describe-regions --profile client-account1 --output table

Validate CloudTrail Across Regions

aws cloudtrail describe-trails --include-shadow-trails --profile client-account1

Validation: Multi-region CloudTrail enabled; Logging enabled for all regions.

If CloudTrail is not configured for multiple regions, it should be reported as a security finding.

10. Assessment Deliverables

The final assessment package should contain:

  • ScoutSuite HTML Report
  • Prowler Compliance Report
  • Manual Validation Evidence
  • Identified Security Findings
  • Risk Rating
  • Remediation Recommendations

11. Recommended AWS Security Baseline

Ensure the following controls are implemented:

  • MFA enabled for privileged accounts
  • Least privilege IAM access
  • CloudTrail enabled with multi-region logging
  • S3 public access blocked
  • GuardDuty enabled
  • Security Hub enabled
  • Regular security posture monitoring
  • Proper logging and alerting configured
